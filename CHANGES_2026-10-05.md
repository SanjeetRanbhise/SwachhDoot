# SwachhDoot – Changes (2026-10-05)

Implemented without replacing the existing application structure:

1. Citizen side
   - Live camera capture using the device camera.
   - GPS is requested when the live camera opens and saved with the complaint.
   - Complaint submission requires a captured/uploaded photo and GPS coordinates.
   - Citizen selects an expected cleaning time: 6, 12, 24, 48 or 72 hours.
   - Expected cleaning deadline is stored and shown in tracking/dashboard.
   - Feedback is available after a complaint is cleaned.
   - Feedback accepts either the complaint database ID or public complaint ID.

2. Waste Management Team side
   - Citizen cleaning deadline is shown on every assigned complaint.
   - Overdue complaints are clearly marked.
   - If a complaint is overdue, a delay reason is compulsory before the WMT can mark it cleaned.
   - Delay reason is stored and displayed with the completed complaint.

3. Admin reports
   - Print Report now prints only the generated report, not the entire dashboard page.

4. Database
   - Existing complaints table is migrated automatically with:
     `expected_cleaning_hours`, `expected_cleaning_at`, and `delay_reason`.
   - Existing complaints receive a 24-hour default deadline when the new columns are first initialized.

5. Validation
   - Frontend TypeScript compilation completed successfully.
   - Backend JavaScript syntax checks completed successfully.
   - Vite production build could not run in this environment because the uploaded node_modules is missing Rollup's platform-specific optional package. Run `npm install` in `frontend` and then `npm run build` locally/Replit.
